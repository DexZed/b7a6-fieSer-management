------- Nest Command -----
-- using pnpm as package manager
pnpm --package=@nestjs/cli --package=@nestjs/schematics dlx nest new . --package-manager=pnpm

-- start dev server
pnpm run start:dev

-- New Resources --
nest g resource [name] --no-spec 

---Command To install all currently installed packages to a new folder (Project Specific)--
-- Prisma 
pnpm dlx prisma@latest orm init --target postgres -> Adds to an existing project
pnpm add prisma@latest @prisma/orm-postgres@latest dotenv -> if problems arise in the previous command.

-- Remaining ---
pnpm add -D @nestjs/jwt @nestjs/config prisma(use this when theres problems with prisma: see above) 
pnpm add class-transformer class-validator


--- Prisma Commands ---
pnpm dlx prisma@latest contract infer --output ./prisma/contract.prisma -> Use this when theres an existing schematics/models and want to create a contract.prisma file

pnpm dlx prisma@latest contract emit -> This refreshes prisma/contract.json and prisma/contract.d.ts so the runtime and query APIs are aligned with the contract you just reviewed. You will use this on schema changes.  

pnpm dlx prisma@latest db sign -> This step matters in two common cases:
                                    - the database has never been signed by Prisma 8 before
                                    - the database was signed earlier, but under an older contract hash
